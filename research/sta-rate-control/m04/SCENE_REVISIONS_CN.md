# M04 场景修订记录

所有修订必须保留旧场景和失败记录；不得在看到 ESTA 结果后放宽门槛。

## v1 → v2（首次 ESTA 飞行前）

上游时间戳修复后，原 v1 PID 的两轮起飞/60 s 悬停/降落脚本均完成，但离线全 armed 窗口的 roll 输出限值检查失败。resume/pid01 在 sample=106832000、111088000 us 分别输出 +0.2070379、-0.1844858，超过冻结的 |c_R|≤0.15。这些时刻在降落命令之后、landed/maybe_landed 标志仍为 false，不能事后删掉或当成已经上锁。首次峰值附近真值向下速度约 0.73 m/s；这是接地附近的现象证据，不构成碰撞动力学根因证明。

依据 STA_MILESTONES_CN.md M04 的“若原 PID 都不满足，先修改场景并记录新预设”，v2 在**尚未进行任何 ESTA 飞行**时将 MPC_LAND_SPEED 从原基线约 0.7 调为 0.3 m/s。仅减慢场景的降落阶段，PID/ESTA 使用相同设置、每轮 disarm 后恢复原值；不修改 PID 增益、悬停/激励、模型、g、nu 上限或验收阈值。PID 的比较基准也必须重新取得，不能拼入 v1 成功片段。v1 原参数和协议保留在 protocol_v1_history.json 及每次运行目录。

这不是原 M00 参数零差异复跑：报告必须明确指出场景参数差异。独立分析器只允许协议精确列出的场景参数值，原控制参数仍核对 M00。

## 日志验收器修正（非门槛修订）

修复后的 resume/pid01 首次分析因 backward 诊断事件暂停。人工复核：切换 FIFO 一次带来 3 个已经发布过的旧样本和一个等时样本，全部 published=false，真实控制输出始终相隔 4000 us。分析器现验证等时/倒退拒绝关系、倒退候选必须属于已观察到的历史、事件序号连续且没有零时间，仍要求控制样本严格递增且 armed raw_dt 无异常。不把被拒绝的 FIFO 历史样本当成下游实际时间倒退，也不允许悄悄忽略未知倒退。原分析退出 1 日志保留；修正后的分析继续发现 roll 超限，因此该轮仍为未通过。

## v2 → v3（仍未进行 ESTA 飞行）

v2_pid01 完成飞行，已通过 roll 输出边界，但参数审计失败。源码 MulticopterLandDetector::_update_params 会在 LNDMC_Z_VEL_MAX > MPC_LAND_SPEED 时把前者改为后者（commit_no_notification）。因此慢降落实际需要同时固定这两个参数。v2 的 cleanup 恢复了降落速度，却遗漏了自动变化的检测阈值；不能称为完整参数恢复。

v3 显式列出 MPC_LAND_SPEED=0.3、LNDMC_Z_VEL_MAX=0.3，记录并恢复两者，默认原值分别 0.7、0.5。v3_pid01 启动时一次性用 M04_REPAIR_V2_LAND_PARAM=1 修复我们留下的 0.3 检测阈值（严格校验预期状态后恢复为 0.5，记录命令）；后续不需要该环境变量。v2 原日志/协议/失败结果保留，不拼入 v3 三轮对照。

另一个参数审计项 COM_CPU_MAX=-1 已在 M00 完整 params_all.txt 核对为原值，只是初始 ULog 的已使用参数子集未列出；补充精确值及来源指纹到 late_logged_baseline.json，没有允许任意参数漂移。
