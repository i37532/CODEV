## 2. 实现内容及语义

| 文件/入口 | 作用 |
|---|---|
| `src/modules/mc_rate_control/RateControl/ControllerSelection.hpp` | 验证原始 int32 请求，管理 requested/effective、拒绝原因和 pending |
| `src/modules/mc_rate_control/RateControl/RateControlDispatcher.hpp` | 控制器统一入口，M01 仅转发给原 RateControl，每周期更新一次 |
| `src/modules/mc_rate_control/MulticopterRateControl.cpp/.hpp` | 使用 dispatcher；在读取最新解锁状态后更新选择状态，提供 status 命令 |
| `src/modules/mc_rate_control/mc_rate_control_params.c` | 新增 `MC_RTC_MODE=0`、`MC_STA_AXES=0` 及元数据 |
| `msg/rate_ctrl_selection.msg`、`msg/CMakeLists.txt` | 独立选择诊断话题，保留旧 rate_ctrl_status 消息格式 |
| `src/modules/logger/logged_topics.cpp` | 默认日志增加按变化发布的选择诊断话题 |
| `RateControl/ControllerSelectionTest.cpp`、`RateControl/RateControlDispatcherTest.cpp` | 选择策略和逐样本精确等价回归 |
| `RateControl/test/M00RateControl.cpp/.hpp` | 独立、冻结的 M00 PID 参考，仅链接单测 |
| `research/sta-rate-control/scripts/run_m01.py`、`analyze_m01.py` | 实际参数检查、PID 飞行和 ULog 对照 |

参数约定：MODE=0 请求 PID；1/2 分别预留 ESTA/ISTA。AXES 位掩码为 roll=1、pitch=2、yaw=4，有效范围 0–7；PID 下这些掩码均不启用实验轴，实际 axes 始终为 0。非法有符号值先验证再使用，不做 uint8 截断，256 不会被截成 PID。

| 请求情况 | request_status | effective_mode / axes | pending |
|---|---|---|---|
| PID + 有效掩码 | 0 accepted | 0 / 0 | 解锁期间请求改变时为 true |
| ESTA/ISTA + 有效掩码 | 1 unsupported | 0 / 0 | 同上 |
| MODE 不在 0–2 | 2 invalid_mode | 0 / 0 | 同上 |
| MODE 合法但 AXES 不在 0–7 | 3 invalid_axes | 0 / 0 | 同上 |

请求值和有效性立即可观察，解锁期间的新请求相对上次已处理配置标记 pending；disarm 后处理最新请求并清除 pending。回到上次已处理请求会取消 pending。`accepted` 表示请求值合法，是否等待处理还需看 pending。M01 的有效控制器始终为 PID；拒绝请求不会清空积分，也不会调用未实现算法。这里的“拒绝”指控制器选择，不新增 commander 禁止解锁行为。

现有 PID 参数更新仍在原来的 parameter_update 回调位置执行，保留 1 s 订阅节流；不延迟原 PID 增益生效。`RateControl.cpp/.hpp` 逐字节未改。原模块的 disarm/机型积分重置、landed/maybe_landed 传递、饱和反馈、dt 限幅、前馈、推力、输出有限值处理、电池缩放和 termination 分支保持原调用顺序。

新诊断话题在首次有效 gyro 回调和选择状态变化时发布，避免每周期重复警告。拒绝原因也进入控制台。`mc_rate_control status` 从 uORB 读取快照，避免直接跨线程读取控制器状态。消息枚举和内部枚举用编译期断言核对。

现场检查包括：起飞前验证默认 0/0、请求 ESTA/ISTA、非法 mode=-1/256、非法 axes=-1/8、PID 非零掩码并恢复默认；悬停中请求 ESTA/ISTA，确认 unsupported + pending，同时 actual PID；取消请求，再把 PID 的 AXES=7 保持 pending 穿过降落；disarm 后确认 pending 清除，最后恢复并保存 0/0。

结果为 **1/1 次冒烟成功**，运行器和 ULog 分析退出码均为 0。16 项现场选择检查通过；13 项起飞前/悬停观察的原始时间戳及字段与 ULog 精确匹配。ULog 共记录 16 个选择状态样本，effective_mode 全为 0、effective_axes 全为 0。最终 disarm/cleanup 用现场 CLI 记录验证，因为 SDLOG_MODE=1 在首次 disarm 时可能已停止记录。

- 起飞 → Hold → 悬停 **60.120 s** → 降落自动上锁。
- armed 飞行区间无已记录的 failsafe/failure-detector；悬停输出全部有限，logger dropout=0。
- 悬停角速度 RMSE（R/P/Y）：`0.003879 / 0.003007 / 0.001781 rad/s`。
- 最大估计倾角 `0.7094°`，最大绝对估计高度跟踪误差 `0.1501 m`。
- 控制模块计数估计 `249.983 Hz`；输出日志仍约 `20 Hz`，未修改 SDLOG_PROFILE=131。

与 M00 初始参数相比，仅增加两个默认选择参数，以及已有飞行编号/累计时间的差异。ULog 的 26 条运行期参数记录全部涉及这两个新参数，原 PID 增益/滤波等无修改。两个参数按各自更新事件可出现过渡组合（例如先改 mode 再改 axes），本阶段所有组合均维持 PID；CLI 检查等待最终请求组合生效。后续开放算法时需按 M03 的配置整体校验约定继续完善。

一次冒烟不构成 PID 性能的统计对比；全速 TV/频谱、原始噪声带宽与随机种子的限制沿用 M00。M03 的高频算法日志、异常控制状态机及 M02 的 ESTA 内核均未实现。
