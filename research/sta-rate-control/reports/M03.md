## 2. 交付和关键接口

### 2.1 公共保护适配器

新增 `src/modules/mc_rate_control/StaRateControl/StaProtection.{hpp,cpp}` 与测试，建立在 M02 内核上；M02 数学实现不变。接口为 `begin(config, frame)`、`step(rate, rate_sp, feedback)`、`acknowledge()` 及只读状态查询。

单位沿用计划：s = rate − rate_sp，rad/s；a、nu 为 rad/s²；归一化命令 c = a/g，不是物理电机力矩。lambda1 单位为 (rad/s²)/sqrt(rad/s)，lambda2 为 rad/s³。step 保留旧 nu 计算本步输出，再提出 nu_next；三轴候选更新全部成功才一起提交，每个 begin 帧最多 step 一次。

保护适配器已链接供生命周期观察使用，但真实模块写死 `frame.experiment_active = false`，不调用 step。dispatcher 仍仅允许 PID；MODE=1/2 仍拒绝，effective_mode/effective_axes 始终 0/0。并未增加可飞 ESTA 增益，也没有偷偷接入 roll 轴。

新增 MC_STA_L1_R/P/Y、MC_STA_L2_R/P/Y、MC_STA_G_R/P/Y、MC_STA_NU_R/P/Y，共 12 个参数，默认均为 0（未配置）。由原参数更新回调整组读取；armed 修改只 pending，disarmed 时有效配置整组接受并递增 config_seq。无效请求保留旧配置；取消请求不改变状态。选中轴要求有效正增益/g 与正 nu 限制，c_limit 默认 1 且必须在 (0,1]。未选中轴允许未配置值。

**config_valid 仅说明请求的适配器参数域合法，config_seq 仅表示已存储实验配置；两者不等于 dispatcher 已启用新算法，更不等于完成 g 标定。** 原 PID 增益仍按原来时序立即更新，不套用实验参数的 armed 冻结规则。

| 生命周期事件 | 实验状态行为 |
|---|---|
| 首次观察 | Startup 清零；若落地同时记录 Landed |
| disarm | 清零 nu；不自动清除故障 latch |
| 退出实验或禁用角速度环 | 清零，记录 Exit |
| 进入 landed | 清零一次；持续 landed 不反复产生 reset |
| maybe_landed | 冻结更新，不重复清零 |
| disarmed 接受新配置 | 整组生效、清零、config_seq 加一 |
| 显式 acknowledge | 仅 disarmed 允许清除 latch 并 reset |

raw_dt 在 clamp 前按有符号传感器时间差独立检查，首次为 NaN；重复、倒退、零时间、超过 20 ms、短于 125 μs 分别诊断。125 μs～20 ms 是本阶段工程边界，不是 ESTA 稳定性证明。原 PID 的 dt clamp 和执行语义未改。

活动实验路径会锁存首次配置/测量/时间/数值故障。数值失败不部分提交轴状态，返回 valid=false 与 NaN 哨兵；**该返回不是零力矩安全策略，也没有发送给执行器**。M03 不实现自动 PID 接管；未来若选择接管，仍须完成有效测量、PID 状态初始化及过渡测试。

mixer 反馈要求 valid bit、非零时间、非未来时间、同发布时钟年龄不超过 20 ms。无效/过期反馈保守冻结 nu；有效反馈按轴正负饱和位与 delta_nu/g 的方向，只冻结加深饱和的增量，允许退饱和。另有 nu 限幅和 c 限幅，限制原因分别可见；不能把这些局部保护当作整机安全证明。

### 2.2 日志与 PID 等价边界

新增并注册 `msg/sta_rate_ctrl_status.msg`，队列 32；记录 sample/publish 时间、发布序号、实际更新序号、requested/effective mode/axes、配置状态、raw_dt/PID dt、s/nu、raw/applied 命令、限制、reset/fault、落地/armed 状态，以及独立 PID 重算所需 P/D/FF、积分前后和测量量。

update_seq 仅在实际调用原 PID update 时递增；publish_seq 对诊断帧递增。禁用/termination 不冒充更新或保持输出，held 本阶段为 false；未实现 M09 分频。PID 下 a_raw、xi、virtual_state 为 NaN，ISTA branch 为 255，不把不适用数据填成有效零值或 sliding。PID 下实验 nu 为 0，experiment_updated 为 false。

原 RateControl、dispatcher、selector 源码不变；原积分 reset、饱和订阅读取、update、有限性处理、电池缩放及 termination 分支语义保留。c_raw 是真实 PID 输出，c_applied 是真实发布的归一化命令，不是物理扭矩。

`multirotor_motor_limits` 增加生产者 update_seq；MixingOutput 在原发布位置递增，不改 mixer 数学。**原 motor 话题队列仍为 1**，避免改变 PID 读取语义。最终版本在原 PID 消费 motor_limits 的位置缓存同一份反馈，嵌入新诊断话题；没有额外订阅读取抢先改变观察值。仅 Iris 使用的 MixingOutput 生产者完成序号插桩；其他硬件发布者未验证。消息 ABI 已变化，构建时相关发布者/订阅者须一起重新生成。

默认新状态为 100 ms 日志间隔，HIGH_RATE 下为 0 ms，同时注册 motor_limits 两个实例的 0 ms 日志。场景保留 SDLOG_PROFILE 全部旧位，131 | 16 = 147，重启 logger 使用 `-b 256 -r 1000 -t -f`；结束恢复并核实原 profile=131 和 MC_STA_L1_R=0。未改全局默认日志 profile。

## 3. 场景、解析与中止

`run_m03.py` 复用原 Iris 启动器，拒绝已有仿真/QGC 占用，要求开始选择参数为 0/0。飞行中仅将未生效的 MC_STA_L1_R 从 0 改为 0.125，检查 armed pending 且 config_seq 不变，降落 disarm 后才应用；随后恢复保存。没有修改 PID 增益、关闭失联保护或导入 DP1000 参数。

监视器检查错模式、故障/abort、无效活动 PID 测量/输出/时间、缺失/停滞/过期诊断。启动估计器发布前仅允许有界 warmup 宽限，不能无诊断起飞。异常走现有 finally，停止自己启动的 SITL、保留失败数据、尝试恢复参数；不是发送零力矩或自动切 PID。脚本采样约 0.5 s，CLI 操作还有有界超时，**不是机载实时安全控制器**。没有在空中注入数值故障；异常分支离线自动测试。

`analyze_m03.py` 通过初始 profile 明确选择研究 ULog，不按文件名猜测；校验指纹、独立 float32 原 PID 运算顺序、真实 actuator 发布、运行状态、配置冻结和参数差异。统计发布序号/实际更新序号的缺口，检查重复/倒退及 uint32 回绕；不插值补齐并伪称无损。

M00 ULog 初始参数只是当时已使用的子集。重启 logger 后出现的 5 个旧参数，逐值对照 M00 完整 CLI 导出，而非任意放行；来源/指纹见 `m03/late_logged_baseline.json`。SDLOG_PROFILE 的延迟参数通知仅允许“值为 147 且时间早于 takeoff”，不允许任意运行期 profile 变化。

27,093 个实际 PID 更新样本的三轴 c_raw 与独立 float32 重算逐位相同，位差 0；电池缩放逐位相同，24,752 个可对齐 actuator 样本与真实发布逐位相同。该结果是“同输入/状态下 PID 运算不变”，不是不同仿真运行轨迹逐位相同或零额外计算开销证明。

run02 已观察原 motor 缺失 1,385 个；run03 重采仍缺失。因此分析器明确输出 `suitable_for_full_rate_tv=false`。本阶段符合计划“重采或标记不适合 TV/频谱”的门槛，不生成全速 TV/频谱论文结论。新状态及内嵌反馈仅在本次悬停窗口无观察到缺失；其他窗口、其他机型或更大日志负载仍须独立验证。
