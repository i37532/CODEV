# selector修复后单次PID诊断

预算：新种子11001、1次PID，不补飞，不计入正式配对验收。沿用用户持续授权，执行前记录绑定源码/协议的授权回执；不需要再次询问普通批次。仅Iris SITL、不push、不实机。

不修改原protocol10文件、控制律、控制参数、模型/world、起飞/60秒观察/32秒X激励/降落任务、reset/故障/安全边界和时间门槛。新的flight.py只更换入口路径/授权绑定，测试逐字核对其余实现。原监视器任何失败仍立即结束并保留失败。

仅额外启用SDLOG_PROFILE位10，保留现有位，通常147→1171。提高已有6实例姿态/位置/status和3个IMU/加速度话题为全发布率；真实采样率、时间匹配和缺样从ULog报告，配置全速不等于没有丢样。不提高sensor/control频率，不更改FIFO位的调度策略，不把真值送入控制。离线发现原profile147已占满255槽，后加载的部分视觉话题本就未加入；新位只调整已有订阅，测试要求话题数量/成员不变，不新加FIFO，也不声称记录了FIFO原始数组。

执行顺序：离线4项Python接线与日志profile C++测试、原控制/selector回归、构建；freeze.py审计种子并冻结资产，明确提交；干净提交重新构建/复核，再run.py --execute。运行目录已存在就拒绝，1次后停止，保存完整EEPROM并恢复；冻结数据/原始ULog另存外部目录。

诊断分析预先关注：①实际速度和rate均PID；②采样时间是否仍倒退；③削顶轴/时刻、3个IMU实际量程/计数、6实例fault变化和selector顺序；④触地前后估计/真值与land状态（真值仅离线）；⑤高频覆盖、最大间隔、dropout/损坏。缺少必要数据就记录“不足以判断”，不把诊断成功等同V04接受；不改判旧九批失败。

本轮保持MPC_LAND_SPEED=0.7，不在看完诊断前改变它。高频负担可能影响调度，必须披露；依然要求旧实时日志传输/大小/安全守卫，失败不能放宽后原地重跑。
