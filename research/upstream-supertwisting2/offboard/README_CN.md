## 计划比较的两类任务

| 顺序 | 任务 | 系统 |
| --- | --- | --- |
| O001–O004 | 持续位置目标＋空中小高度阶跃 | PID → 原版 STA2 → RSTA → RISTA |
| O005–O008 | 持续位置起飞＋空中小 Z 速度脉冲 | PID → 原版 STA2 → RSTA → RISTA |

最多 8 次，每个系统、每个任务只有 1 次，属于探索性比较，不作显著性或普遍排序结论。每组第一轮 PID 包含在预算内，不额外安排安全试飞。首个安全或必需有效性失败停批，不补飞、不调参、不扩大预算。

共同流程：重启与原生日志预热 → 发送地面目标至少 2 秒且至少 20 个实际目标 → Offboard/解锁 → 16 秒五次曲线升至相对高度 2.5 m → 最多等待 15 秒，连续 3 秒满足高度误差 ≤0.3 m、|vz|<0.2 m/s → 悬停 10 秒 → 相应测试 → 恢复 2.5 m 并重新满足稳定条件 → 16 秒平滑下降至 0.3 m → AUTO_LAND、落地上锁。

位置测试：高度目标由 2.5 m 阶跃到 2.8 m，保持 8 秒；再回到 2.5 m，保持 8 秒。XY 位置和初始 yaw 固定，不发送速度或加速度前馈。起飞时间单独报告，空中阶跃才用于分析较少受起飞状态机影响的响应。

速度测试：空中仅 Z 使用速度目标，XY 仍保持位置；向上 0.2 m/s 持续 2 秒 → 零速度 4 秒 → 向下 0.2 m/s 持续 2 秒 → 零速度 4 秒。目标积分净位移为零，**实际位移不保证为零**，仍须检查高度和位置安全边界。NED 中向上对应负 vz。

两类任务均记录 XYZ 实际速度与相对起始位置；四条算法曲线叠加，速度图与位移图分开。目标线须明确标成“目标”，不混同第五个算法。本批主要激励 Z，不据此宣称验证了 XY 阶跃响应。

## 为什么不直接复用旧起飞结果

旧实验通过 Navigator 起飞和保持；新任务要记录实际接收到的 Offboard 目标，分开检查“目标是否及时到达”和“控制器是否及时跟踪”。四个系统同一个外部位置目标，仍不等于它们内部合成的速度目标逐样本相同。

原版 STA2 保持独立原仓库：其角速度环使用 STA，XY 速度环为误差归一化 PID，Z 速度输出仍为 PID。RSTA/RISTA 则是本项目 XYZ 速度环变体、角速度 PID。因此这是**四套系统对比**，不是四种只改速度控制律的纯算法试验。

复用既有 `manifest04_pid.json` 中的参数与固件来源，不将旧飞行算入新样本。当前分支 `research/upstream-supertwisting2`，HEAD `1f6fe1c7a46c22ea41a6a6a51c51498142ca6d62`。主固件 SHA-256 为 `a1ebc57f178c07713f14e2ed423c8b1d27dad251bc70e6047411bfa7877695d8`；原版固件为 `4416c1dc1b93c9a7c96dd0d252b100d1a209cbe5dc0d8baff808c96609983716`。两者本次只读核验一致。

注意主固件是此前 `8079e17177e3edb597d8da1597081a82cbd6747a` 加当时已登记未提交源码的构建，不是声称由当前干净 HEAD 重新构建。正式开飞前仍需核对全部源码、子模块、模型和插件，而不只看 HEAD。

## ROS 接线和依赖验证

设计链：ROS 2 任务节点 → `/codev_offboard/target` → 独立桥接节点订阅 → 本机 MAVLink → PX4 Offboard。代码调用真实 `rclpy` 发布/订阅；这是自定义 ROS/MAVLink 桥，**不是 MAVROS**，也不是直接调用订阅函数假装经过 ROS。

目标采用显式 LOCAL_NED：位置掩码 2552；XY 位置＋Z 速度掩码 2524。只使用本机 `14540 ↔ 14580`，ROS domain 42、localhost-only。时间轨迹由 PX4 native `time_boot_ms` 推进，墙钟只作通信与停滞看门狗，不代替仿真时间。

机器原有 ROS 工作区依赖缺失的 `/opt/ros/foxy`，不可用。本次在 `/home/yr/.local/share/codev-ros-offboard` 隔离安装最小 ROS 2，没有 sudo、系统安装、修改 shell 配置或改动原工作区。首个有界尝试遇到 TLS、缓慢下载和依赖解析问题；利用缓存第二次有界续装成功，保留了第一次阻塞记录。

实际安装 Python 3.14.10、ROS 2 Humble/rclpy 3.3.22、CycloneDDS、pymavlink 2.4.50；独立 DDS 往返约 0.3022 秒。目录约 1.01 GiB，版本及包哈希锁在该目录。运行器保留原系统 Python 的分析依赖，ROS 单独进程使用隔离环境，不混入旧 Python 二进制扩展。

两套 PX4 均转发已知 GCS 心跳，桥接器仅忽略本运行器 `255/190` 且类型为 GCS 的转发心跳，不把它当作原生无人机状态；其他来源的原生测量仍拒绝。此路径已在第二次本机回环验证。

PX4 Offboard 要在切换前及运行期间持续收到目标；仅安装 ROS 或提高发布频率不能证明端到端目标已经生效。[PX4 v1.13 Offboard 文档](https://docs.px4.io/v1.13/en/flight_modes/offboard)。隔离环境方案参考 [RoboStack 官方安装说明](https://robostack.github.io/micromamba.html)。
